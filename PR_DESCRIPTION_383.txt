This branch, when used with the upstream MCP sanitization change, adds an optional final-stage sanitization step to CodeGraph's MCP response pipeline so that indexed source code and any other context the MCP tools return to a downstream agent can be redacted before it ever leaves the MCP server. The motivation is that indexed codebases routinely contain sensitive values, the obvious cases being email addresses, phone numbers, US Social Security numbers, credit card numbers, and common API key strings such as OpenAI project keys (sk-...) and AWS access key IDs (AKIA...). Before this change the MCP server forwarded ToolHandler output directly to the client, which is fine for a local developer workflow but not acceptable in regulated or compliance-sensitive environments. With this change CodeGraph now offers an explicit, opt-in, pre-LLM redaction control without removing MCP functionality. The default behavior is unchanged: redaction only activates when the operator turns it on.

The implementation is split across three concerns. First, there is a new module `src/mcp/sanitization.ts` that owns all the redaction logic. It exposes two small public functions: `sanitizeText(input)` which runs the built-in redaction pipeline over a string and returns the rewritten string plus a count of replacements, and `sanitizeToolResult(result)` which is the entry point used by the MCP tool dispatcher. The built-in pipeline applies five regex passes in order: email addresses become `[REDACTED_EMAIL]`, US SSNs become `[REDACTED_SSN]`, North American phone numbers (with a length predicate so 10-to-15 digit matches are kept and short numeric false positives are skipped) become `[REDACTED_PHONE]`, credit-card-shaped digit runs (with Luhn validation to reduce false positives) become `[REDACTED_CREDIT_CARD]`, and common API key patterns (the `sk-` prefix with a long alphanumeric tail, plus the AWS `AKIA[0-9A-Z]{16}` shape) become `[REDACTED_API_KEY]`. Each pass returns the rewritten string and an incremental replacement counter so the caller can decide whether anything actually changed. The result wrapper only allocates a new content array when at least one block was changed, so the disabled path is allocation-free.

Second, the same module supports an optional custom sanitizer hook loaded from a path supplied through `CODEGRAPH_SANITIZE_HOOK` (or, equivalently, the new `--sanitize-hook <modulePath>` CLI flag). The hook is `require`d once and cached by its resolved path; the contract is that the loaded module exports a function with the signature `(text: string) => string | Promise<string>`, accepting either a default export or a named `sanitize` export. The hook runs after the built-in redaction pass and runs in the same async `sanitizeToolResult` helper, so user-supplied logic layers on top of the built-in rules. Hook load errors and runtime errors are logged once each to stderr and do not crash the MCP server. The hook is invoked through `Promise.resolve(...)` so synchronous hooks work as well as async ones.

Third, the MCP tool dispatcher is wired up to apply sanitization at exactly the right point. `ToolHandler.execute()` in `src/mcp/tools.ts` runs each tool, wraps the result with the existing worktree notice and staleness notice helpers, and now passes the wrapped result through `sanitizeToolResult(...)` before returning it to the MCP client. Sanitization is therefore applied centrally, once, to final tool output, after the worktree and staleness wrappers, so response behavior remains consistent and redaction is enforced before anything leaves MCP. The new module is imported at the top of `src/mcp/tools.ts` and the only structural change inside `execute()` is a small refactor: the status branch now uses `result = await this.handleStatus(args); break;` instead of a direct `return` so that all branches share the same sanitization cleanup. There is one small carve-out: when the requested tool is `codegraph_status`, the response skips the worktree and staleness wrappers (because those wrappers embed the pending-file list as a first-class section inside `handleStatus` already), but sanitization still runs on the bare result, so a status response with PII in it is still scrubbed.

Operator controls are exposed two ways. The CLI gains two new options on `codegraph serve`: `--sanitize`, which sets `CODEGRAPH_SANITIZE=1`, and `--sanitize-hook <modulePath>`, which forwards into `CODEGRAPH_SANITIZE_HOOK` after resolving the path to an absolute one if necessary (the absolute-vs-relative resolution lives in `src/bin/codegraph.ts` so the rest of the codebase can trust that the env var is an absolute path). The same two variables can also be set directly in the environment, which is the form most container deployments will use. Both controls are additive: setting only the built-in flag runs only the built-in pipeline, setting only the hook loads only the custom sanitizer, and setting both layers the custom sanitizer on top of the built-in one.

Tests live in `__tests__/mcp-sanitization.test.ts` and cover four cases. The first case feeds a single string containing an email, a phone number, an SSN, a credit card, an OpenAI-shaped key string, and an AWS-shaped key string to `sanitizeText` and asserts that all six are redacted to the expected placeholder tokens and that the original literals are gone. The second case drives the full `ToolHandler.execute()` path with `CODEGRAPH_SANITIZE=1` set and a fake `buildContext` that emits a user email, and asserts that the returned MCP content contains `[REDACTED_EMAIL]` and no longer contains the original address. The third case is the symmetric negative case: with both env vars unset it asserts that the same input passes through unchanged. The fourth case writes a small CommonJS hook file to a temporary directory, points `CODEGRAPH_SANITIZE_HOOK` at it, drives an MCP call whose fake output contains a `customer_id: 42` field, and asserts that the hook's regex replaced the field with the marker string the hook itself defines. The hook test also cleans up the temp directory in a finally block so it does not leave artifacts behind. The env vars are saved and restored around every test in an `afterEach` hook so the suite is hermetic across runs.

Documentation is updated in three places. `README.md` gains a short "MCP sanitization (optional)" section immediately below the install block with two example invocations, a short description of each flag, and the corresponding env-var equivalents, plus a new line in the commands cheat sheet for `codegraph serve --mcp --sanitize`. `site/src/content/docs/reference/cli.md` gains a parallel "MCP sanitization" subsection in the CLI reference page. `site/src/content/docs/reference/mcp-server.md` gains a parallel "Optional privacy hardening" subsection in the MCP server reference page, immediately after the basic `codegraph serve --mcp` snippet and before the section that lists the tools the agent will use. `CHANGELOG.md` records the same change under `[Unreleased]` / `### New Features` so it rolls into the next minor release notes whenever the unreleased bucket is promoted.

Backward compatibility is enforced by the opt-in design: `builtInSanitizationEnabled()` and `loadSanitizeHook()` both default to no-op when their respective env vars are unset, and `sanitizeToolResult(...)` short-circuits and returns the original result object unchanged in that case, so existing MCP clients see byte-identical output. The wrapper allocation in `ToolHandler.execute()` only runs when at least one block was rewritten by either the built-in pipeline or the hook, so the disabled path is also allocation-free in the content array. No existing public API changes; no existing CLI flag changes; no documentation page is removed or rewritten, only extended.

Validation steps for review: `npm run build` to type-check and bundle, `npx vitest run __tests__/mcp-sanitization.test.ts` to run the new sanitization suite, and `npx vitest run __tests__/mcp-tool-allowlist.test.ts` to confirm the new dispatcher wiring does not regress the allowlist-related tool tests, since both tests exercise `ToolHandler` directly. End-to-end manual verification with a real MCP client can be done by starting `codegraph serve --mcp --sanitize` against a fixture repo whose source contains the literal patterns listed in the first test case and confirming the agent only ever sees `[REDACTED_*]` placeholders, then restarting without the flag and confirming the agent sees the original text.
